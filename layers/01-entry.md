# 1. 사용자 접점

사용자가 요청을 제출하고, 승인하고, 결과를 확인하는 계층입니다. 데스크톱 앱과 메신저 연동으로 구성됩니다.

## 책임

- 요청을 받아 중앙 게이트웨이에 제출합니다.
- 사용자 PC를 대상으로 한 파일 작업과 명령을 해당 PC에서 실행합니다. 모델은 중앙에서 실행됩니다. 모델이 요청한 도구 호출만 PC로 전송되어 실행됩니다.
- 다른 장비에서 실행된 작업의 목록과 승인 대기 항목을 표시합니다.
- 메신저에서는 짧은 응답과 승인 버튼을 표시합니다. 근거 자료는 요청이 있을 때만 전송합니다.

## 책임 범위 밖

- 작업 상태 저장. 상태는 중앙 서버의 작업 원장에 저장됩니다.
- 다른 장비의 파일 처리.
- 모델 계정 키 보유.

## 경계에서의 검사

| 검사 | 설명 |
| --- | --- |
| 읽기 범위 | 읽기는 사용자가 선택한 폴더로 제한됩니다. |
| 쓰기 방식 | 쓰기는 먼저 작업 사본에 적용됩니다. 사용자가 변경 내용을 검토하면, 앱은 원본의 해시를 다시 비교해 변경되지 않았음을 확인한 뒤 적용합니다. |
| 명령 실행 | 허용 목록, 로컬 승인, OS 샌드박스가 필요합니다. 네트워크 접근은 차단됩니다. |
| 접근 모드 변경 | 실행 중에는 변경할 수 없고, 모델이 도구 인자로 변경할 수도 없습니다. |
| UI와 메인 프로세스 | UI 프로세스는 파일과 네트워크에 직접 접근할 수 없습니다. 제한된 인터페이스로 메인 프로세스에 요청합니다. |

## 교환하는 데이터

| 데이터 | 방향 | 필드 |
| --- | --- | --- |
| 사용자 키 | 앱 → 게이트웨이 | 사용자마다 고유한 키. 공유 키를 쓰면 게이트웨이가 요청자를 구분할 수 없습니다. |
| 요청 | 앱 → 게이트웨이 | 요청 ID, 실행 위치(이 PC 또는 실행 장비), 내용 |
| 이벤트 | 게이트웨이 → 앱 | 일련번호가 있어 연결이 끊긴 뒤 이어서 받을 수 있습니다. |
| 도구 호출 | 게이트웨이 → 앱 | 실행 권한이 PC 1대로 한정됩니다. 다른 PC는 가져갈 수 없습니다. |
| 도구 결과 | 앱 → 게이트웨이 | 앱은 실행 전 의도와 실행 후 결과를 로컬에 저장한 다음 결과를 전송합니다. |

## 장애 시 동작

- **앱 종료**: 해당 PC에서 실행 중이던 작업은 취소됩니다. 실행 장비에 배정된 작업은 계속됩니다.
- **PC 전원 꺼짐**: 해당 PC를 대상으로 한 작업은 PC가 켜질 때까지 큐에 보관됩니다. 파일이 해당 PC에만 있으므로 다른 장비로 옮기지 않습니다.
- **도구 결과 미전달**: 앱은 저장된 결과만 재전송합니다. 결과가 불확실한 동작은 다시 실행하지 않습니다.

## 미결 사항

- 메신저 사용자를 게이트웨이 사용자에 매핑하는 방법. 매핑 테이블을 둘지, 회사의 통합 로그인을 사용할지입니다.
- 사용자가 실제로 읽고 승인하게 하려면 승인 화면이 변경 내용을 어느 정도까지 표시해야 하는지.
