# 4. 관측

실행 기록을 수신하고 표시하는 계층입니다. 요청 처리 경로에 포함되지 않습니다. 다른 구성 요소가 전송한 기록을 저장하는 역할만 합니다. 예시 도구로 Langfuse를 사용합니다.

## 책임

- 게이트웨이가 처리하는 모든 요청의 수락, 전달, 완료를 기록합니다.
- 여러 장비에 걸쳐 하나의 식별자를 유지합니다. PC에서 중앙 서버로, 다시 실행 장비로 이동하는 작업을 하나의 기록으로 조회합니다.
- 시간이 어디에 쓰였는지, 작업이 어디서 실패했는지, 모델 사용량이 얼마인지 표시합니다.

## 책임 범위 밖

- 요청의 지연이나 차단.
- 권한 판정의 기준 기록 역할. 누구에게 무엇이 허용되고 거부됐는지의 기준 기록은 각 호스트의 감사 로그와 작업 원장입니다.
- 작업 품질의 판정. 기록만으로는 응답이 정확했는지 알 수 없습니다.

## 기록 출처

| 출처 | 기록 내용 |
| --- | --- |
| 게이트웨이 탭, 사용자 쪽 | PC와 메신저에서 온 요청의 수락과 완료 |
| 게이트웨이 탭, 실행 장비 쪽 | 실행 장비가 작업을 가져온 시각과 보고한 시각 |
| 모델 게이트웨이 | 각 모델 호출의 모델, 토큰 수, 소요 시간 |
| 에이전트 호스트 | 도구 호출과 권한 판정 |
| 데스크톱 앱 | 승인 대기 시간과 실행 시간. 게이트웨이를 통해 제출합니다. |

## 기록 구조

| 단위 | 의미 | 예 |
| --- | --- | --- |
| trace | 게이트웨이가 수락한 실행 1건 | 작업 1건 |
| span | 시작과 끝이 있는 구간 | 게이트웨이 턴, 도구 왕복, 호스트 기동, 승인 대기 |
| event | 한 시점의 사실 | 권한 판정. 거부와 차단은 경고로 표시합니다. |
| generation | 모델 호출 1건 | 모델, 토큰 수, 소요 시간 |

두 번째 유즈케이스(퇴근 전 작업 위임)의 기록 예시입니다. 이름은 예시입니다.

```text
trace  run-7c1e   PC-A → 중앙 → VM-1
├ gateway.turn       수락, 대상 VM-1
├ task.create        위임 토큰 발급
├ task.claim         대기 4초
├ host.spawn         기동 소요 시간
├ policy.decision    허용
├ tool               위키 읽기
├ model.request      generation × 6
├ approval.wait      13시간
├ apply              해시 일치
└ terminal           완료
```

## 경계에서의 검사

- **기록은 비동기로 전송합니다.** 전송이 실패해도 요청에 영향이 없습니다.
- **본문은 기본적으로 제외합니다.** 모델, 토큰 수, 소요 시간, 판정 결과만 전송합니다. 프롬프트와 응답 본문은 프로필별로 활성화합니다. 다중 사용자 환경에서 모든 본문을 수집하면 관측 서버가 가장 민감한 데이터 저장소가 됩니다.
- **사용자는 가명으로 기록합니다.** 가명은 서버가 인증한 신원에서 생성합니다. 클라이언트가 보낸 이름은 신뢰하지 않습니다.
- **실행 장비는 관측 서버의 키를 보유하지 않습니다.** 실행 장비의 기록은 게이트웨이를 통해 제출됩니다.
- **긴 작업은 짧은 기록으로 나눕니다.** 승인 대기처럼 몇 시간 지속되는 구간은 시작과 종료를 따로 기록합니다.

## 장애 시 동작

- **관측 서버 중단**: 작업은 계속되며 해당 기간의 기록은 누락됩니다. 누락된 기간은 작업 원장과 호스트의 감사 로그에서 확인할 수 있습니다.
- **재시작으로 구간의 종료 시각 유실**: 종료 시각을 임의로 만들어 넣지 않습니다. 별도의 복구 기록을 연결합니다.

## 미결 사항

- 기록의 보존 기간.
- 사용자 PC와 서버의 시계가 다를 때 구간 길이를 어느 시계 기준으로 계산할지. 각 프로세스가 측정한 소요 시간을 사용하는 편이 안전합니다.
