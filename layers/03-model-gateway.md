# 3. 모델 게이트웨이

에이전트의 모델 요청을 중계하는 서버입니다. 모델 계정의 자격 증명은 이 서버에만 존재합니다. 에이전트는 작업마다 생성한 단기 키를 사용합니다.

## 책임

요청은 다음 순서로 처리됩니다.

| 순서 | 단계 | 설명 |
| --- | --- | --- |
| 1 | 단기 키 검증 | 호스트별 비밀로 만든 서명과 만료 시각을 확인합니다. |
| 2 | 경로와 모델 확인 | 허용 목록에 없는 경로와 모델을 거부합니다. |
| 3 | 요청 재구성 | 허용된 필드만으로 새 요청을 구성합니다. 알 수 없는 필드는 제거합니다. |
| 4 | 예산 확인 | 프로필마다 일일 한도가 있습니다. 한도에 근접하면 더 작은 모델로 전환하거나 요청을 거부합니다. |
| 5 | 계정 풀로 전달 | 계정 풀이 계정을 선택하고 해당 계정의 토큰을 추가해 모델 제공사로 전송합니다. |
| 6 | 사용량 기록 | 프로필별 사용량을 기록합니다. |
| 7 | 관측 기록 | 호스트가 전달한 trace ID에 모델 호출을 연결합니다. |

계정 풀은 여러 계정을 보유하고, 한 계정이 한도에 도달하면 다음 계정으로 전환하는 프록시입니다. 기존 오픈소스 프록시를 그대로 사용하며, API 키 계정으로 구성합니다.

## 책임 범위 밖

- 어떤 작업을 할지 결정하는 것.
- 파일이나 명령의 실행.
- 사용자 권한 평가. 이는 호스트의 정책이 담당합니다.

## 교환하는 데이터

**단기 키**

| 필드 | 설명 |
| --- | --- |
| 호스트 | 키를 생성한 호스트 |
| 프로필 | 예산과 허용 모델을 조회하는 기준 |
| 작업 ID | 이 작업에만 유효 |
| 만료 시각 | 예상 작업 시간보다 조금 길게 설정 |
| 서명 | 호스트마다 고유한 비밀로 서명합니다. 한 호스트가 다른 호스트의 키를 생성할 수 없습니다. |

## 경계에서의 검사

- 호스트마다 서명 비밀이 달라야 합니다. 비밀을 공유하면 읽기 전용 호스트가 쓰기 권한이 있는 호스트로 위장할 수 있습니다.
- 계정 풀은 모델 게이트웨이 뒤에 배치하고 직접 노출하지 않습니다.
- 소비자(중앙 게이트웨이와 모델 게이트웨이)마다 별도의 키를 부여해 사용량을 분리해서 집계합니다.

## 주의 사항

요청을 재구성할 때 안전 관련 필드가 제거되지 않도록 허용 목록에 명시해야 합니다. 해당 필드가 없어도 요청은 성공하므로, 사용량 기록을 확인하기 전에는 누락을 알아채기 어렵습니다.

## 장애 시 동작

- **예산 초과**: 설정에 따라 더 작은 모델로 전환하거나 요청을 거부합니다. 거부는 관측에 기록됩니다.
- **풀의 모든 계정이 한도에 도달**: 한도가 초기화될 때까지 대기하거나 실패를 반환합니다. 무인 작업에는 대기가 적합합니다.
- **서명 오류 또는 만료**: 요청을 거부합니다. 호스트는 새 키를 생성해 재시도할 수 있습니다.

## 유사한 결정을 한 제품

- [Coder AI Gateway](https://coder.com/solutions/ai-governance): 제공사 키가 제어 서버 밖으로 나가지 않으며, 모델 요청을 사용자별로 기록합니다.
- [agentgateway](https://github.com/agentgateway/agentgateway): 에이전트, 도구, 모델 간 트래픽에 정책을 적용합니다.

## 미결 사항

- 데스크톱 앱의 모델 요청도 이 게이트웨이를 거치게 할지, 중앙 게이트웨이가 계정 풀로 직접 전송할지.
- 예산을 프로필 단위로만 설정할지, 사용자 단위로도 설정할지.
