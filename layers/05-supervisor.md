# 5. 감독 프로세스

클라우드 VM이나 사내 서버에서 상시 실행되는 유일한 프로세스입니다. 모델 접근 권한과 계정 키가 없습니다. 명령 집합이 고정되어 있어 침해되더라도 권한을 상승시킬 수 없습니다.

## 책임

감독 프로세스는 정확히 7개의 명령을 지원합니다.

| 명령 | 기능 |
| --- | --- |
| 등록 | 장비마다 고유한 키로 중앙 서버에 장비를 알립니다. |
| 하트비트 | 실행 중임을 주기적으로 보고합니다. |
| 작업 가져오기 | 중앙 서버로의 아웃바운드 연결을 통해 자신에게 배정된 작업만 수신합니다. |
| 호스트 기동 | 등록된 에이전트 호스트 컨테이너만 기동합니다. |
| 작업 전달 | 작업과 위임 토큰을 같은 장비의 호스트에 전달합니다. |
| 보고 | 결과, 승인 요청, 프로필 해시를 중앙 서버로 전송합니다. |
| 호스트 종료 | 상주 프로필이 아니면 작업이 끝난 뒤 호스트를 종료합니다. |

에이전트의 실행 방식은 두 가지입니다. 대부분의 프로필은 작업이 도착하면 기동하고 작업이 끝나면 종료합니다. 로그 감시처럼 지속적으로 감시해야 하는 프로필은 계속 실행합니다. 두 방식 모두 상시 실행되어야 하는 프로세스는 감독 프로세스뿐입니다.

## 책임 범위 밖

- 임의의 명령 실행. 고정된 기동·종료 명령만 존재합니다.
- 중앙 서버 외의 대상에 대한 연결.
- 모델 호출.
- 중앙 서버에 연결할 수 없는 상태에서의 새 작업 시작.
- 권한 평가. 감독 프로세스는 위임 토큰의 내용을 확인하지 않고 호스트에 전달합니다.

## 경계에서의 검사

- **연결 방향**: 장비는 중앙 서버로 가는 아웃바운드 연결만 엽니다. 사내망 안의 서버도 방화벽 인바운드 규칙을 추가하지 않고 참여합니다.
- **등록 키**: 장비마다 고유합니다. 유출된 키로 다른 장비를 사칭할 수 없으며, 해당 키만 폐기하면 됩니다.
- **기동 가능한 호스트**: 중앙의 호스트 등록부에 등록된 호스트만 기동할 수 있습니다.

## 교환하는 데이터

| 데이터 | 방향 | 필드 |
| --- | --- | --- |
| 등록 | 장비 → 중앙 | 장비 이름, 등록 키, 실행 가능한 프로필 |
| 하트비트 | 장비 → 중앙 | 시각, 실행 중인 호스트, 각 프로필의 해시 |
| 작업 | 중앙 → 장비 | 작업 ID, 프로필, 위임 토큰, trace ID |
| 보고 | 장비 → 중앙 | 작업 ID, 상태, 결과 또는 승인 요청 |
| 작업 요청 | 장비 → 중앙 | 로컬 이벤트를 작업으로 제출할 때 사용합니다. 등록된 트리거 범위 안에서만 수락됩니다. |

## 장애 시 동작

- **중앙 서버 연결 불가**: 감독 프로세스는 새 작업을 시작하지 않고 대기합니다. 진행 중인 작업은 끝까지 실행하고, 보고는 연결이 복구될 때까지 보관합니다.
- **장비 재부팅**: 감독 프로세스는 OS 서비스 관리자에 의해 다시 시작됩니다. 진행 중이던 작업의 결과를 알 수 없다고 보고합니다. 중앙 서버는 해당 작업을 `불명`으로 기록하고 자동으로 재실행하지 않습니다.
- **호스트 무응답**: 제한 시간이 지나면 감독 프로세스가 호스트를 종료하고 실패를 보고합니다.

## 유사한 결정을 한 제품

- [Claude Managed Agents: self-hosted sandboxes](https://platform.claude.com/docs/en/managed-agents/self-hosted-sandboxes): 고객 장비의 워커가 큐에서 작업을 가져옵니다. 워커는 아웃바운드 HTTPS만 필요합니다.
- [Cursor self-hosted cloud agents](https://cursor.com/blog/self-hosted-cloud-agents): 워커가 아웃바운드 연결을 열고 그 연결로 도구 호출을 수신합니다.
- [LangSmith Deployment의 hybrid 구성](https://docs.langchain.com/langsmith/deploy-hybrid): 고객 쪽 구성 요소가 제어 서버를 폴링해 변경 사항을 가져옵니다.
- [Preloop](https://github.com/preloop/preloop): 러너가 아웃바운드 WebSocket으로 접속합니다.

## 미결 사항

- 감독 프로세스 자체를 누가 어떻게 업데이트할지. 자체 업데이트는 고정 명령 집합 원칙에 어긋납니다.
- 새 장비에 등록 키를 설치하는 절차.
