Harnel

Harnel(하넬)은 사내 AI 에이전트의 배치 구조에 붙인 이름입니다. 에이전트를 사용자 PC, 중앙 서버, 실행 장비(클라우드 VM과 사내 서버)에 배치하고 한 곳에서 관리합니다. 구성 요소는 모두 이미 제품이나 오픈소스로 존재하며, 이 문서는 그 구성 요소를 나누는 기준을 정의합니다. 가상 장비 7대와 유즈케이스 5개로 작업 1건이 어떤 구성 요소를 거치는지 단계별로 확인할 수 있고, 구성 요소를 선택하면 내부 구조가 열립니다. 설계 초안이며 구조 전체를 구현하거나 검증하지는 않았습니다.

작업 원장
작업의 요청자, 배정된 장비, 현재 상태를 기록하는 중앙 서버의 저장소입니다.
감독 프로세스
실행 장비마다 상시 실행되는 프로세스입니다. 모델 접근 권한과 계정 키가 없으며, 작업을 받아 에이전트를 기동·종료하는 일만 합니다.
관측 탭
게이트웨이가 요청을 수락하거나 전달할 때 Langfuse로 기록을 전송하는 지점입니다. 요청 처리와 별도로 전송하므로 지연을 추가하지 않습니다.
위임 토큰
중앙 서버가 발급하는 단기 서명 토큰입니다. 사용자, 프로필, 작업 ID, 만료 시각을 담습니다.
배치도 · 작업 흐름

유즈케이스를 선택하고 단계를 이동하면 해당 단계에서 동작하는 구성 요소와 연결이 표시됩니다

주황색은 해당 단계에서 동작하는 구성 요소와 연결, 분홍색은 Langfuse로 전송되는 기록, 빨간색 선은 차단된 시도입니다. 구성 요소를 선택하면 내부 구조가 열립니다. 장비, 인물, 요청 내용은 모두 가상입니다.

구축 순서

5단계로 구축하고, 단계마다 유즈케이스 하나를 실행해 검증합니다

  1. 중앙 서버 구성과 관측 탭

    중앙 서버에 게이트웨이, 모델 게이트웨이, 계정 풀, Langfuse를 배포합니다. 게이트웨이의 사용자 쪽 관측 탭을 추가합니다.

    완료 후사용자 PC의 폴더 작업이 중앙 서버를 거쳐 실행되고 Langfuse에서 기록을 조회할 수 있습니다.
  2. 작업 원장과 등록 API

    작업 원장, 호스트 등록, 작업 가져오기, 결과 보고를 추가하고 실행 장비 쪽 관측 탭을 추가합니다.

    완료 후연결된 앱 없이 작업이 완료되는지 스텁 호스트로 시험할 수 있습니다.
  3. 실행 장비 1대와 예약 트리거 1개

    사내 서버에 감독 프로세스와 읽기 전용 프로필을 배포하고, 하루 1회 실행되는 트리거를 추가합니다.

    완료 후07:00 문서 점검이 사용자 없이 실행되고 결과가 슬랙으로 전송됩니다.
  4. 위임 토큰, 승인 대기열, 쓰기 호스트

    사용자의 신원을 실행 장비까지 전달하고, 쓰기는 승인 대기 상태에서 중단되게 한 뒤 VM-1의 쓰기 호스트를 활성화합니다.

    완료 후저녁에 위임한 작업을 다음 날 승인해 완료할 수 있습니다.
  5. 정책 등록부, 이벤트 트리거, 작업 분담

    프로필 해시 등록과 트리거 범위를 추가하고, 감시 VM의 이벤트 트리거와 지식 위키 기반 작업 분담을 연결합니다.

    완료 후빌드 실패 자동 대응이 동작하고, 침해 유즈케이스의 차단 지점이 모두 갖춰집니다.
